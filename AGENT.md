### OPTIONAL — defaults are baked into `config.py`

```

```

**Agent rule:** if writing `.env`, never overwrite an existing key without an explicit user-confirmed instruction. Append-with-update (preserving comments) is the wizard's behavior — replicate it.

## 3. Install procedure (deterministic)

```yaml
prerequisites:
  - python: ">=3.11"
  - claude_cli: "available on $PATH; `claude --version` must succeed"
  - git: any
  - macos: launchd available (Linux: cron or systemd)

steps:
  - id: clone
    cmd: git clone <repo> && cd csv

  - id: venv
    cmd: |
      cd agent
      python3 -m venv .venv
      .venv/bin/pip install -e .

  - id: env
    action: create_file
    path: .env
    template: .env.example
    user_input_required:
      - TELEGRAM_CMPRSSN_BOT_TOKEN
      - TELEGRAM_CMPRSSN_CHAT_ID
      - TELEGRAM_CMPRSSN_TOPIC_PULSE
      - TELEGRAM_CMPRSSN_TOPIC_COMPRESSION
      - TELEGRAM_CMPRSSN_TOPIC_CODEBOOK
      - TELEGRAM_CMPRSSN_TOPIC_FRONTIER
      - TELEGRAM_CMPRSSN_TOPIC_ONCHAIN
      - TWITTER_BEARER_TOKEN
      - BLUESKY_EMAIL
      - BLUESKY_APP_PASSWORD

  - id: build_handles
    cmd: agent/.venv/bin/python agent/scripts/build_handles.py
    expect_stdout_contains: "wrote .* total .* x-enabled .* rss-enabled"

  - id: smoke_test
    cmd: cd agent && .venv/bin/python -m src.orchestrator --dry-run
    expect_stdout_contains: "ingest complete"
    expect_exit_code: 0

  - id: schedule_macos
    when: platform == "darwin"
    cmd: |
      cp agent/deploy/com.cmprssn.signal.plist ~/Library/LaunchAgents/
      launchctl unload ~/Library/LaunchAgents/com.cmprssn.signal.plist 2>/dev/null || true
      launchctl load ~/Library/LaunchAgents/com.cmprssn.signal.plist
    verify: launchctl list | grep com.cmprssn.signal

  - id: schedule_linux
    when: platform == "linux"
    instruction: "Add to crontab: 0 6,12,18,0 * * * cd <abs_repo>/agent && .venv/bin/python -m src.orchestrator"
```

**Preferred entrypoint:** `python3 agent/scripts/setup_wizard.py` (executes all of the above interactively).

## 4. Runtime contract

### Entrypoint

```
cd agent
.venv/bin/python -m src.orchestrator [--dry-run]
```

`--dry-run` flag: executes the full pipeline (fetch + score + cap selection) but skips Telegram writes. Database WRITES still occur (posts are upserted with quant/qual scores) — this is intentional for backfill workflows.

### Exit codes

```
0  — success (regardless of how many posts were sent)
1  — config error (missing env, missing handles.json, etc.)
2+ — unexpected exception (logged + raised)
```

### Output artifacts per run

```
agent/logs/run-YYYY-MM-DD.log     # appended
agent/data/agent.db               # row updates
telegram channel posts             # 0–15 messages + 1 digest to General
```

### Side effects

- HTTP requests to: `api.twitter.com`, `bsky.social`, `api.telegram.org`, RSS hosts
- Subprocess spawn: `claude -p` (one per post that passes quant gate)
- File writes: `data/agent.db`, `data/x_user_cache.json`, `logs/*.log`

## 5. Database schema (SQLite)

```sql
CREATE TABLE posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    platform TEXT NOT NULL,              -- 'x' | 'bluesky' | 'rss'
    platform_id TEXT NOT NULL,           -- tweet_id | post_uri | rss entry id
    author_handle TEXT NOT NULL,
    author_slug TEXT,
    author_followers INTEGER,
    text TEXT NOT NULL,
    url TEXT NOT NULL,
    likes INTEGER DEFAULT 0,
    retweets INTEGER DEFAULT 0,
    replies INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,            -- ISO8601 UTC
    fetched_at TEXT NOT NULL,            -- ISO8601 UTC

    -- Stage 1 (quant)
    passed_quant INTEGER DEFAULT 0,
    quant_ratio REAL,

    -- Stage 2 (qualitative)
    qualitative_score INTEGER,           -- 0–10
    qualitative_topic TEXT,              -- pulse | compression | codebook | frontier | onchain
    qualitative_layers TEXT,             -- JSON array of L0–L8
    qualitative_reason TEXT,
    qualitative_relevant INTEGER,        -- 0/1

    -- Publish state
    posted_to_tg INTEGER DEFAULT 0,
    posted_topic TEXT,
    posted_at TEXT,
    tg_message_id INTEGER,

    UNIQUE(platform, platform_id)        -- dedup key
);
```

**Migration policy:** the schema is created with `CREATE TABLE IF NOT EXISTS`. Adding columns requires an explicit migration — do not silently drop and recreate.

## 6. Pipeline contract

```
fetch (x + bluesky + rss)
  → dedup against posts.UNIQUE(platform, platform_id)
  → store with passed_quant=0
  → quant gate
      RSS:        auto-pass (return True, 1.0)
      X/Bluesky:  likes >= floor AND likes/followers >= ratio_min
  → mark passed_quant on survivors
  → qualitative gate (claude CLI subprocess, 1 per surviving post)
      input:  agent/src/prompts/signal_score.md + post text
      output: {relevant, score, topic, layers, reason} as JSON
      env:    CLAUDECODE + CLAUDE_CODE STRIPPED before subprocess.run
  → mark qualitative_*; survivors are relevant=true AND score >= MIN_QUAL_SCORE
  → rank by (score DESC, likes DESC)
  → apply caps: ≤ MAX_POSTS_PER_RUN total, ≤ MAX_POSTS_PER_TOPIC_PER_RUN per topic
  → publish to Telegram (1 post / second)
  → mark posted_to_tg=1 with tg_message_id
  → build digest, post to General
```

**Failure isolation:**
- A single ingest source failing (e.g., X 402, Bluesky login) does NOT abort the run. Other sources still execute. Only the failing source's posts are absent from this cycle.
- A single post failing to publish (e.g., Telegram 429) does NOT abort the run; it's logged with `posted_err += 1`.
- A single Claude CLI timeout returns `relevant=False, score=0` — the post is dropped, the run continues.

## 7. Configuration mutation rules

If the agent is asked to change behavior:

| Change | How |
|---|---|
| Add/remove a monitored handle | Edit `individuals.csv` or `companies.csv`, then re-run `agent/scripts/build_handles.py` |
| Change schedule cadence | Edit `agent/deploy/com.cmprssn.signal.plist` `<key>StartCalendarInterval</key>` array, then `launchctl unload && launchctl load` |
| Tune signal volume | Update `MIN_QUAL_SCORE` in `.env` (no code change) |
| Tune per-run caps | Update `MAX_POSTS_PER_RUN` / `MAX_POSTS_PER_TOPIC_PER_RUN` in `.env` |
| Add a topic channel | (1) Add a topic in Telegram, (2) add `TELEGRAM_CMPRSSN_TOPIC_<NAME>` to `.env` + `config.py`, (3) update `topic_for()` mapping, (4) update `format.py` `THREAD_EMOJI`, (5) update `signal_score.md` routing rules |
| Add an ingest source | New module under `agent/src/ingest/`, wire into `orchestrator.run_once()`, add a `<source>_handles()` filter to `handles.py` |
| Disable an unverified handle | Add slug to `DISABLED_SLUGS` in `agent/scripts/build_handles.py`, rebuild |

## 9. Common failure modes and fixes

```yaml
- symptom: "RuntimeError: Missing required env var: TELEGRAM_CMPRSSN_BOT_TOKEN"
  cause: ".env not at repo root or key missing"
  fix: "verify file at <repo_root>/.env (not agent/.env); re-run setup_wizard.py"

- symptom: "x: 402 CreditsDepleted"
  cause: "X API credits exhausted"
  fix: "top up at https://console.x.com/; no code change"

- symptom: "Claude CLI refused to run / 'cannot run inside Claude Code'"
  cause: "CLAUDECODE or CLAUDE_CODE env var inherited"
  fix: "qualitative.py already strips these; verify the strip code is intact at score/qualitative.py"

- symptom: "telegram: Bad Request: message thread not found"
  cause: "topic ID is wrong or pointing to General with non-zero thread_id"
  fix: "for General topic, set TELEGRAM_CMPRSSN_TOPIC_GENERAL=0; for others, recopy from t.me/c/<chat>/<topic>/<msg> URL"

- symptom: "rss: malformed feed (...)"
  cause: "site serves non-XML-strict RSS (Beehiiv is a known offender)"
  fix: "non-fatal; logged as warning. To repair, replace feedparser parse with raw httpx + lenient parse — out of scope for routine deploys."

- symptom: "FileNotFoundError: handles.json"
  cause: "build_handles.py not run after CSV edit"
  fix: "run agent/scripts/build_handles.py"
```

## 10. Do not

- Do not call the Anthropic API. Inference goes through the local `claude` CLI exclusively.
- Do not install `twikit` (legacy dep, removed in favor of X API v2).
- Do not commit `.env`, `agent/data/agent.db`, or `agent/data/x_user_cache.json`.
- Do not modify the schema's `UNIQUE(platform, platform_id)` constraint — it's the dedup key.
- Do not increase poll cadence beyond hourly without explicit operator approval — it burns X API credits.
- Do not bypass per-run caps — they exist to prevent burst spam.
- Do not invoke `claude` with the inherited environment — strip `CLAUDECODE` and `CLAUDE_CODE` first.
